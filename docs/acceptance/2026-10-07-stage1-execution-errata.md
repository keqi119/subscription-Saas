## 证据和结论等级

- **C（确认）**：实际失败及对应代码/输入/复现足以定位所述缺陷；仍不把未观察的下游结果补成成功。
- **R（同类复现）**：已复现并修正一个同类缺陷，但原失败缺少决定性现场证据，不能声称唯一历史根因。
- **U（未明）**：错误和残留状态已确认，具体触发原因未证明。后续通过不能倒推原失败原因。
- **P（执行前拦截）**：静态审核或准备阶段发现；不能计入真实发布失败，也不能据此声称运行验证完成。

主要证据为 [H1 执行台账](../../.superpowers/sdd/2026-10-05-stage1-h1-snapshot-host/progress.md)（下称 **P**，以下标明行号）及 [10 月 1 日状态记录](2026-10-01-stage1-r3-delivery-status.md)。被忽略目录中的证据属于本机保留材料，不随 Git 文档自动交付；原失败记录不得覆盖。原始字节摘要和 canonical JSON 摘要分别记录，不互换。

**性质与证据等级是两个维度。** “代码瑕疵”包括产品、发布适配器及诊断脚本的确定性逻辑错误；“编排错误”包括使用顺序、冻结输入和授权时间绑定错误；“环境兼容”指稳定的宿主路径/挂载/API 形态差异；“环境抖动”需实际瞬态网络/资源/服务证据。泛化错误、后一次通过、耗时不同都不充分，无法归因时标“未明”。同一条可以有多层原因，但不能把编排错误包装成不可控环境抖动。
