## Status

The guarded helper and native entry are implemented. `decryptSnapshot()` preserves the existing consumer UNKNOWN and locks, and returns only `PLAINTEXT_AUTHENTICATED` with `promotionEligible:false`. It does not run restore or append a successful consumer execution. The selector is captured before asynchronous preparation, and the published plaintext is independently hashed through the retained descriptor before it is accepted.

Root review found three concrete boundaries worth correcting: a mutable launch selector could change repository/operation after validation; the published output could be replaced during post-decrypt checks; and a valid later `ProcessSizeMax=1 G` assignment could be ignored, retaining an earlier zero. The first two have direct RED/GREEN regressions. The last is confirmed against upstream [systemd's size parser](https://raw.githubusercontent.com/systemd/systemd/v255/src/basic/parse-util.c) and [coredump configuration parser](https://raw.githubusercontent.com/systemd/systemd/v255/src/coredump/coredump.c); the fix retains the entire final RHS and requires exact `none`/`0`. Its regression refuses before opening the RSA key. A passed-profile/public-record mismatch also has a RED/GREEN regression. Raw nonsecret OS command/proc observations are retained within a bounded readback; no key/backing-file contents are recorded.
