# Stage 1 Trusted Build Input Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This document authorizes no real key, storage, CI, database, or deployment action.

**Goal:** Prepare reviewable H1 identity, H2 authoritative build custody, and independent expected-schema inputs so the existing fixed trust reader can later admit one accurately frozen Stage 1 candidate.

**Architecture:** Keep H1 profile/owner approval on the actual owner host, add a narrow H2 producer only inside the already protected build workflow after an existing approved private storage capability is identified, and derive expected schema from an isolated reference PostgreSQL 17 database populated from the frozen source migrations. The consumer remains `loadFixedManualProfile`, `verifyManualBuild`, and R2.2's fixed input reader; no second trust parser, shared Schema, or success flag is introduced.

**Tech Stack:** Node 22, pnpm 11.4.0, Prisma 7.8.0, PostgreSQL 17.11, GitHub Actions protected `trusted-image-build`, existing release-foundation custody and manual evidence contracts.

**Spec:** [Audit closure Task 10](./2026-09-22-stage1-audit-driven-closure-plan.md#任务-10提前解决-h1h2-与-expected-schema-的实际输入), [R1 §2.6 and H1/H2](./2026-09-06-stage1-r1-manual-trust-and-authorization-plan.md#26-固定-h1buildoperation-输入权威r13-与-r22-的唯一边界), [R2 expected-schema admission](./2026-09-06-stage1-r2-runner-migrate-verify-plan.md#task-r21人工请求baseline-与-handler-映射).

## Review Focus

1. A profile with a correct digest but the wrong actual host/principal or a root with a wrong owner must fail H1 before key/session/index access; Task 1's read-only gate records this.
2. An Actions delivery object, local copy, receipt with a requested 90-day date, or writer's own readback must not satisfy H2; Task 2 tests independent Get/Head/reader and service retention.
3. A receipt attested by another workflow, source, run ID, or run attempt must fail even if its JSON and proof digest match; Task 2 binds both attestation results to one frozen run.
4. A schema script captured from the H3 target or an unversioned reference database must fail before signing/credential/DB; Task 3 tests origin and fixed tool/source identity.
5. Existing 180-day and 210-day retained objects must not be shortened by the new 90-day path; Tasks 1–3 test policy separation and do not mutate old producers.
