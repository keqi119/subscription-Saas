## 已确认事实

实际四规格输出及独立公共回读字节相同，SHA-256 为 `564de0474f695a8ea933f00bb4ed35fd5084388119b7b754b0fff5d9c8f50d24`。其中 `sourceFresh=SPEC_PRESENT`，其余三个引用为 `ABSENT`。文件存在不代表规格验证完成；保护卷内原件字节尚未独立回读。

同一个 sourceFresh 调用先完成 proof 验签（14.322 秒）、receipt 验签（10.943 秒）及 run API 查询（0.941 秒），随后第二次 proof 验签运行 120.131 秒后被 SIGTERM 终止，最后等待阶段为 `TUF_GITHUB / TUF_ROOT`。保护清理结果记录两卷关闭、swap/core 恢复；独立现场读取确认挂载与 mapper 均不存在、全局锁可用、两条既有 swap 路径存在。不能据此宣称发布或 R3 通过。

## 修复边界与分段复用

修复只补齐规格创建对既有验签作用域的使用，不放宽签名、有效期、动态状态、文件身份及原件变化检查，不改变 create-only 或失败保留规则。定向回归先证实原代码失败，再检验修复；合成 reader 的接线验证与实际信任模块的密码验证次数测试分别说明，不能混称为云端验签成功。

本轮开发前工作区干净，Prisma validate 通过；复用既有服务器 datasource 回读，128 个迁移中仍有 `20260925090000_stage1_operational_completion_terminal_shape`、`20260925091000_stage1_operational_completion_settlement_guard` 两项待应用，未执行迁移。本修复不改变业务行为。

作用域传递回归先在原代码失败，修复后通过；异步关闭回归先证明 `Promise.all` 遇到首个拒绝会提前退出，改用 `allSettled` 等待全部句柄后通过，关闭失败仍返回失败。合成 writer 用例覆盖四种规格入口、输入引用突变、失败后的占位及不可重放。真实信任模块 reader 加合成 GitHub CLI 输出的独立用例通过，确认一次 prepare 中 proof/receipt 各调用一次密码验签入口。该结果是本地集成验证，不是实际 GitHub 验签或网络恢复证明。

原生分段 `38213519287` 已完成的 14 份原件与局部成功结果保留；是否复用到后续候选须核对受影响文件，不因无关源码提交重跑原生工作区段。旧构建、负责人事实、快照准入及 RAM 草案保留真实绑定，不能改写为新候选证据。后续候选签发和新 RAM 权限仍按实际差额处理，真人 SOURCE／SNAPSHOT／ACK 不可由聊天批准替代。
