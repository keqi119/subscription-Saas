# 车辆资产详情页签化重组设计

日期：2026-08-08

状态：已批准（2026-08-08，六个页面设计已逐页确认）

## 1. 背景

当前 Admin 的“车辆资产”页面同时承担车辆列表、待销售价复核、销售价历史以及单车全部维护能力。单车详情被放在宽度约 1120px 的浮层中，保险、权证、BaaS、折旧、商品展示、车况报告、残值预测、估值复核、资本结构和分润等模块继续纵向堆叠。随着车辆资产能力增加，浮层已经出现以下问题：

1. 内容高度和模块数量过大，定位困难，关闭浮层后也难以恢复工作位置；
2. 详情缺少稳定 URL，无法深链、刷新或在新标签页中继续处理；
3. 列表操作、单车操作和领域管理入口混在一起，信息层级不清；
4. 权证资料缺少完整分类和统一入口；
5. 商品展示中的车辆配置及车况信息需要人工重复维护，不能直接复用内部原件；
6. 销售价历史仍占据资产台账的全局页签，但数据本质上属于单车详情。

本次设计参考订单详情页的“独立 URL + 固定摘要头 + 页签”模式，将单车详情从浮层改为独立页面，并按领域重组现有能力。

## 2. 已确认决策

1. 车辆资产台账继续以列表为主，不改为卡片或树形台账。
2. 点击车辆行或“详情”进入 `/vehicles/[id]`，不再打开大浮层。
3. 单车详情固定为六个一级页签：
   - 车辆概览；
   - 权证资料；
   - 保险与电池；
   - 商品展示；
   - 估值与折旧；
   - 资本与分润。
4. 列表页只保留“车辆列表”和“待销售价复核”两个页签；“销售价历史”移入单车“估值与折旧”。
5. 列表行操作只保留“详情”。编辑车辆、变更状态、销售价初始化、季度复核、退车再入池等单车动作移到详情页摘要头或对应页签。
6. 权证资料新增完整的八类清单，并全部强制为后台内部可见。
7. 第八类为“车辆采购支付凭证”，用于保存采购支付产生的银行回单，支持一次上传多个文件并可继续追加。
8. 车辆配置单和车辆检测报告可以在商品展示中引用原件长图；不做 OCR、不复制文件、不把 PDF 暴露到商品页。
9. 商品引用固定到精确的原件文件版本。上传新版本不会静默替换，正在被引用的版本在解除绑定前不能归档或删除。
10. 保险材料保持当前客户可见规则，不套用权证资料的强制内部可见规则。
11. 本次不改造车辆、订单、保险、BaaS、估值、折旧、融资或分润业务流程；只为已确认的权证分类、多文件上传和原件引用增加窄数据/API能力。

## 3. 目标

1. 将单车详情变为可深链、可刷新、可在浏览器新标签打开的独立页面。
2. 使用六个稳定页签重组现有能力，减少超长页面和嵌套浮层。
3. 让用户在单车上下文中完成现有编辑、状态、销售价、估值和资产维护动作。
4. 建立完整、内部可见的车辆权证台账。
5. 消除车辆配置单和车辆检测报告在权证与商品展示之间的重复上传、重复存储和重复录入。
6. 保留现有 RBAC、领域数据来源、状态约束和审计边界。
7. 在不加载全部子域数据的前提下，保证详情首屏响应和页签切换可接受。

## 4. 非目标

本次不包含：

- OCR、图片文字识别、配置参数自动结构化或检测结论自动提取；
- 将 PDF 直接嵌入客户商品展示；
- 新建车辆采购、审批、付款或报销流程；
- 新建保险理赔流程或把保险案件纳入本页；
- 新建 BaaS 合同、折旧、融资、分润或结算领域模型；
- 分润正式结算单、应付款、付款指令或银行支付；
- 自动从融资分摊静默生成资本事件；
- 改变残值预测、估值复核、销售价生效或折旧确认规则；
- 改造客户 Portal 的整体视觉结构；
- 批量迁移或重新分类历史 `OTHER` 车辆材料；
- 在本次设计之外重构 Admin 全局导航或订单详情页面。

## 5. 总体信息架构

### 5.1 列表页

`/vehicles` 保留：

| 页签 | 用途 |
| --- | --- |
| 车辆列表 | 全部车辆资产台账、筛选、分页和新增车辆 |
| 待销售价复核 | 需要季度复核或重新定价的工作队列 |

列表交互：

- 点击行的非交互区域进入 `/vehicles/{vehicleId}`；
- 操作列只显示“详情”；
- 点击“详情”与点击行的结果一致；
- 新增车辆仍位于列表页顶部；
- 现有筛选和分页状态由列表页保留，用户通过浏览器返回时恢复；
- “销售价历史”全局页签删除，历史记录只在具体车辆中显示。

### 5.2 详情路由

基础路由：

```text
/vehicles/{vehicleId}
```

页签和二级分类使用 URL 查询参数，支持刷新和复制链接：

```text
/vehicles/{vehicleId}?tab=documents
/vehicles/{vehicleId}?tab=listing&section=source-media
/vehicles/{vehicleId}?tab=valuation&section=sale-price-history
```

约定：

- 缺少 `tab` 时进入 `overview`；
- 无效 `tab` 或 `section` 回退到当前权限下的第一个有效页面；
- 切换一级或二级分类使用客户端路由替换，不重复加载车辆摘要；
- 页面刷新后恢复相同一级页签和二级分类；
- 车辆不存在返回 404 状态；没有 `vehicle:view` 时显示无权访问，不泄露车辆信息。

### 5.3 详情摘要头

六页共用同一个摘要头：

- 返回车辆列表；
- 车辆编号；
- 当前车辆状态；
- 品牌/车系/车型；
- 车牌号或 VIN；
- 当前销售价及销售价状态；
- 依据权限显示的单车动作。

单车动作包括现有的编辑车辆、变更状态、销售价初始化、季度复核和退车再入池重新定价。动作继续调用原领域接口，不由详情页复制状态规则。摘要头与一级页签在长页面滚动时保持可达。

## 6. 六个一级页签

### 6.1 车辆概览

车辆概览是进入详情后的默认页，提供可扫描的只读摘要，不重复所有领域明细。

主要内容：

1. 核心状态卡：当前状态、当前里程、保险覆盖、下次销售价复核；
2. 基础档案：VIN、车牌、品牌、车系、车型、年款、颜色、首次上牌日期、最近登记日期；
3. 电池基础信息：容量和使用方式；
4. 业务关联：当前订单/Lease/商品展示状态等现有可用关联；
5. 最近状态或里程事件时间线；
6. 进入其他页签的快捷链接。

概览只读取车辆摘要和轻量投影。保险、商品、估值和资本的明细数据在进入对应页签后再加载。

### 6.2 权证资料

权证资料使用“完整度摘要 + 权证清单 + 选中文件/版本详情”布局，不再和保险保单混在同一个折叠块中。

#### 6.2.1 八类权证

| 枚举建议 | 中文名称 | 说明 |
| --- | --- | --- |
| `VEHICLE_REGISTRATION_CERTIFICATE` | 机动车登记证 | 登记证书原件 |
| `VEHICLE_LICENSE` | 车辆行驶证 | 沿用现有行驶证类型 |
| `VEHICLE_INSPECTION_REPORT` | 车辆检测报告 | 商品可引用图片原件；不同于现有“年检材料” |
| `VEHICLE_PURCHASE_AGREEMENT` | 车辆购买合同及附属协议 | 一个批次可包含合同及多个附件 |
| `MOTOR_VEHICLE_INVOICE` | 机动车发票 | 购车发票原件 |
| `OWNER_IDENTITY_DOCUMENT` | 车主信息 | 营业执照或身份证，可多文件 |
| `VEHICLE_CONFIGURATION_SHEET` | 车辆配置单 | 商品可引用图片原件 |
| `PURCHASE_PAYMENT_VOUCHER` | 车辆采购支付凭证 | 银行回单，可一次多文件并持续追加 |

现有 `COMPULSORY_INSURANCE_POLICY` 和 `COMMERCIAL_INSURANCE_POLICY` 继续属于保险保单；`INSPECTION_CERTIFICATE` 继续表示年检材料，不与车辆检测报告合并；`VEHICLE_AUTHORIZATION` 和 `OTHER` 保留兼容，并在“其他内部材料”中展示，但不计入八类权证完整度。

完整度按类别计算：某类至少存在一个未删除、状态为 `ACTIVE` 的文件时计为已齐全，否则计为缺失。多文件数量不增加完整度分子；支付凭证的多个有效批次共同归属同一类别。

#### 6.2.2 可见性

- 八类权证的 `customerVisible` 必须为 `false`；
- Admin 不提供“客户可见”开关；
- API 收到八类权证的 `customerVisible=true` 时返回 400；未传或传 `false` 时统一持久化为 `false`，不能只依赖前端隐藏；
- 车辆采购支付凭证、发票、车主信息和合同等敏感资料不进入 Portal；
- 商品展示对配置单和检测报告的访问由“商品原件绑定”单独授权，不改变原权证的内部可见属性；
- 保险保单附件沿用现有客户可见逻辑。

#### 6.2.3 多文件与版本

车辆材料当前后端只保存上传数组中的第一个文件。为满足已确认需求，新增“上传批次”概念：

- 一次上传中的多个文件形成一个逻辑批次；
- 同一车辆、同一材料类型的批次按 `versionNo` 递增；
- 批次内每个文件仍是一条 `VehicleDocument`，保持现有存储、预览和审计能力；
- 车辆购买合同、车主信息和支付凭证允许同一批次包含多个文件；
- 支付凭证是追加型资料，新批次不会让早期有效回单失效；
- 配置单、检测报告等替换型资料上传新版本后，历史版本继续保留，不自动归档；
- UI 按材料类型和批次分组，展示版本号、文件数、上传时间、上传人和状态；
- 归档是软归档，不物理删除存储对象。

建议增加：

```text
VehicleDocumentBatch
  id
  vehicleId
  documentType
  versionNo
  createdAt
  uploadedBy

VehicleDocument.batchId -> VehicleDocumentBatch.id
```

`@@unique([vehicleId, documentType, versionNo])` 保证并发上传时版本号不会重复。历史 `VehicleDocument` 按车辆、类型和创建时间回填为单文件批次。

#### 6.2.4 权证操作

- 上传权证；
- 一次选择多个图片/PDF；
- 预览与下载单个文件；
- 查看历史批次；
- 追加新版本；
- 归档未被商品引用的批次或文件；
- 查看配置单/检测报告是否被商品引用及引用的精确版本。

单次批量上传默认最多 20 个文件，每个文件继续使用现有车辆材料的 MIME 和大小限制。所有文件先完成格式和大小校验；任一文件不合法时整个请求失败。存储阶段失败时不创建半批次数据库记录，并对已上传对象执行尽力清理和错误记录。

### 6.3 保险与电池

该页不设置二级页签，使用三个同页板块：

1. **保险保单**：当前交强险和商业险、保单号、保险公司、保费、保险金额、起止期、续保提醒、保障责任和保单附件；深度维护跳转现有保单管理；
2. **电池档案**：车辆电池容量、使用方式，以及最新有效车况报告中的健康度、检测日期、循环次数、预估续航和质保到期；
3. **BaaS 电池服务**：仅电池使用方式为 `BAAS` 时展示当前合同、服务商、月租、计费周期、支付日、下次付款日和未支付成本；电池买断车辆显示“不需要 BaaS 服务”。

电池检测数据以最新有效车况报告为来源，本页不维护第二份检测副本。保险和 BaaS 的新增、复杂编辑继续进入现有专用页面。

### 6.4 商品展示

商品展示使用以下二级分类：

| 二级分类 | 内容 |
| --- | --- |
| 展示总览 | 发布状态、Portal 可见、资料准备度、客户即时预览和商品板块顺序 |
| 展示文案 | 标题、副标题、卖点、客户标签、费用说明、申请须知、服务亮点和 FAQ |
| 媒体与原件 | 封面/外观/内饰等现有媒体，以及配置单/检测报告的权证原件绑定 |
| 订阅方案 | 可展示套餐、可见性、推荐项、展示月租和说明 |
| 车况报告 | 现有结构化车况报告的创建、检测项、发布与归档 |

“客户预览”改为摘要头或商品展示页右上角动作，不再占用一个二级页面。

“展示准备度”是运营提示，不新增发布审批流程，也不替代现有发布接口。未配置 FAQ 等建议项不阻止现有发布；缺少被配置为必需的封面、方案或无效原件绑定时显示明确告警。

#### 6.4.1 权证原件引用

只允许两个商品板块建立原件绑定：

| 商品板块 | 允许的权证类型 |
| --- | --- |
| `CONFIGURATION_SHEET` | `VEHICLE_CONFIGURATION_SHEET` |
| `CONDITION_REPORT` | `VEHICLE_INSPECTION_REPORT` |

规则：

1. 只能选择当前车辆、状态有效、MIME 为 JPEG/PNG/WebP 的图片文件；
2. PDF 可以留在内部权证中，但不能成为商品绑定；
3. 每个商品板块同一时间只有一个当前绑定；
4. 绑定保存精确 `documentId`，不复制 bucket/objectKey，不新建媒体文件；
5. 上传权证新版本后，现有绑定不变；
6. 改绑前必须预览并显式确认新文件；
7. 被绑定文件不能归档、软删除或改变为不兼容类型，服务返回 409；
8. 解除绑定后才允许归档；
9. 客户商品页在“车辆配置”和“车况报告”对应板块懒加载原件长图；
10. 如果绑定丢失、文件归档或存储不可用，客户板块隐藏并记录告警，不能导致整个商品页 500。

建议模型：

```text
VehicleListingSourceBinding
  id
  vehicleId
  section                 // CONFIGURATION_SHEET | CONDITION_REPORT
  documentId
  createdAt / createdBy
  updatedAt / updatedBy

unique(vehicleId, section)
```

Portal 不使用 Admin 预览 URL，也不暴露 bucket/objectKey。客户侧受控预览接口在每次请求时校验：车辆商品已发布且 Portal 可见、绑定仍有效、文件属于该车辆和允许类型、文件为图片。权证本身仍保持 `customerVisible=false`。

现有结构化车况报告能力继续保留。商品“车况报告”板块采用唯一优先级：存在有效的检测报告原件绑定时只展示绑定长图，不同时渲染结构化报告；没有有效绑定时才回退到当前已发布的结构化报告。结构化报告仍可维护和发布，但不得自动覆盖原件绑定。这样既保留历史能力，也避免客户页出现两份相互矛盾的车况报告。

### 6.5 估值与折旧

二级分类：

| 二级分类 | 内容 |
| --- | --- |
| 估值总览 | 当前销售价、下次复核、最新预测残值、当前账面价值和趋势对照 |
| 残值预测 | 最新预测、预测点、人工采用值、预测历史和生成/作废动作 |
| 估值复核 | 发起、查看和取消估值复核 |
| 销售价历史 | 初始化、季度复核、退车再入池重新定价的单车历史 |
| 折旧管理 | 当前折旧策略摘要、计划数、已确认记录数和专用管理入口 |

能力边界保持不变：

- 残值预测不自动覆盖当前销售价；
- 人工采用残值只保存在预测点并作为估值/收益测算参考；
- 发起估值复核只创建待审核记录；
- 只有审核通过才更新当前销售价并写入销售价历史；
- 折旧策略和折旧确认仍由现有折旧领域管理。

“待销售价复核”列表页签是跨车辆工作队列；点击车辆进入本页后执行季度复核或查看估值依据。

### 6.6 资本与分润

二级分类：

| 二级分类 | 内容 |
| --- | --- |
| 资本总览 | 采购价、取得方式、自有资金、债务本金、覆盖金额/比例、利息试算和 ROE 数据准备度 |
| 资本事件 | 初始采购、债务融资、融资解除、租赁/受托及其他现有事件和审计记录 |
| 融资分摊 | 来自融资工具的本车本金分摊、比例、有效期和补录资本事件状态 |
| 分润规则 | 当前及历史规则、分润基础、比例/固定金额/保底、结算周期和有效期 |
| 分润试算 | 指定日期区间的基础金额、固定成本、车主分润和平台留存 |

融资分摊以融资工具为权威来源。存在融资分摊但缺少对应资本事件时显示“待补录”，允许使用现有能力补录；系统不静默生成资本事件。

分润试算明确标注为经营测算。它不会创建正式结算单、应付款、付款指令或银行付款记录。

## 7. 组件和代码边界

当前 `apps/web/src/app/vehicles/page.tsx` 已接近 6000 行。本次页面拆分必须同时做有针对性的组件拆解，避免把原浮层整体复制到新路由。

建议结构：

```text
apps/web/src/app/vehicles/page.tsx
apps/web/src/app/vehicles/[id]/page.tsx
apps/web/src/app/vehicles/_components/
  vehicle-list.tsx
  vehicle-detail-shell.tsx
  vehicle-summary-header.tsx
  vehicle-overview-tab.tsx
  vehicle-documents-tab.tsx
  vehicle-insurance-battery-tab.tsx
  vehicle-listing-tab.tsx
  vehicle-valuation-tab.tsx
  vehicle-capital-tab.tsx
  ...现有领域子组件
```

边界要求：

- 列表组件只负责筛选、分页、工作队列和导航；
- `VehicleDetailShell` 只负责车辆摘要、一级页签、URL 状态和权限路由；
- 每个一级页签只加载自己的领域数据；
- 现有保单、BaaS、折旧、残值、估值、资本和分润组件优先抽取复用，不复制请求和状态转换逻辑；
- 表单/模态框归属到使用它们的领域页签；
- 格式化、标签和枚举继续使用共享常量；
- 不做与本次页面重组无关的全局组件重写。

## 8. 数据加载与状态管理

1. 详情路由首次只加载车辆基础详情和用户权限；
2. 一级页签首次激活时加载对应子域数据，之后在当前页面会话内缓存；
3. 二级分类共享同一一级页签的数据加载结果；
4. 保存、发布、归档或状态变更成功后只刷新受影响的投影和摘要，不整页重载；
5. 请求切换车辆或页签时使用取消信号或请求序号，防止旧响应覆盖新页面；
6. 长图使用懒加载、受控预览 URL 和占位骨架，不在详情首屏下载；
7. 单个子域加载失败只影响对应卡片/页签，用户可单独重试；
8. 详情基础数据加载失败时显示页面级错误和返回列表入口。

## 9. 权限与安全

### 9.1 Admin 权限

- 详情路由基础访问要求 `vehicle:view`；
- 权证页要求 `vehicle_document:view`，上传/归档要求 `vehicle_document:manage`；
- 保险、BaaS、折旧、估值、资本和分润板块继续使用各自现有权限；
- 用户有一级页签中部分板块权限时，只显示有权数据；没有任何板块权限时隐藏该页签；
- 所有操作权限在 API 端继续强制校验，前端隐藏按钮不是安全边界。

### 9.2 文件安全

- 权证存储继续使用私有对象存储；
- 所有预览按文档 ID 查找，不接受客户端 bucket/objectKey；
- 商品原件接口验证车辆归属、绑定类型、文档状态和商品可见性，防止 IDOR；
- 响应使用实际 MIME、内联文件名和现有安全响应头；
- 敏感权证不进入 Portal 商品响应、日志或前端埋点；
- 支付凭证文件名可展示给授权 Admin，但银行账号等内容不进入可检索文本字段。

## 10. API 影响

### 10.1 复用接口

车辆详情、保单、BaaS、折旧、商品展示、媒体、订阅方案、车况报告、残值预测、估值复核、资本结构、资本事件、分润规则和分润试算继续调用现有接口。

### 10.2 窄新增接口

建议新增：

```text
GET    /vehicles/:id/document-batches
POST   /vehicles/:id/document-batches                 // multipart files[]
POST   /vehicle-document-batches/:batchId/archive

GET    /vehicles/:id/listing-source-bindings
PUT    /vehicles/:id/listing-source-bindings/:section
DELETE /vehicles/:id/listing-source-bindings/:section

GET    /portal/catalog/vehicles/:vehicleId/source-documents/:section/preview
```

兼容要求：

- 现有 `GET/POST /vehicles/:id/documents` 和单文件预览继续可用；
- 旧页面和保险管理不被新批次响应结构破坏；
- 新批量上传接口返回批次元数据和 `items[]`；
- 绑定接口只接受允许类型的图片文档 ID；
- 归档被引用文件返回 409 和可读错误信息；
- 现有 `PATCH/DELETE /vehicle-documents/:id` 同样执行绑定完整性校验，不能绕过批次归档接口解除引用保护；
- Portal 原件预览不复用 Admin 权限接口。

## 11. 数据迁移与部署顺序

1. 添加八类权证所需的新 `VehicleDocumentType` 枚举值；
2. 新增 `VehicleDocumentBatch` 和 `VehicleListingSourceBinding`；
3. 给 `VehicleDocument` 增加可空 `batchId`；
4. 按车辆、类型、创建时间将历史文档回填为单文件批次；
5. 回填验证后再根据实际数据库能力决定是否把新写入路径的 `batchId` 设为强制；历史兼容读取必须保留；
6. 先部署兼容旧 Web 的 API 和迁移，再部署新车辆详情 Web；
7. 新 Web 验证后移除旧详情浮层入口，但保留同一领域 API；
8. 回滚 Web 时旧列表和单文件接口仍可使用；新增表和枚举保留，不做破坏性回滚。

## 12. 异常处理

| 场景 | 行为 |
| --- | --- |
| 车辆不存在或已删除 | 详情页显示 404，并提供返回车辆列表入口 |
| 无基础权限 | 显示无权访问，不请求子域数据 |
| 单个页签接口失败 | 页签内显示错误与重试，不影响摘要头和其他页签 |
| 批量上传含非法文件 | 整批拒绝，说明具体文件和原因 |
| 上传中途存储失败 | 不创建半批次记录；尽力清理已上传对象并记录错误 |
| 绑定错误类型/PDF/其他车辆文件 | API 返回 400/409，不改变原绑定 |
| 归档正在引用的原件 | API 返回 409，提示先解除商品绑定 |
| Portal 原件绑定失效 | 隐藏对应商品板块，记录告警，不影响商品其他内容 |
| 新权证版本上传 | 保留原绑定和历史版本，提示运营是否主动改绑 |
| 资本/分润数据不完整 | 展示缺失原因和“不支持试算”，不伪造 0 值 |

## 13. 测试策略

### 13.1 Web 单元与组件测试

- 列表行和“详情”导航到正确 URL；
- 返回列表恢复筛选和分页；
- 一级/二级分类与 URL 双向同步；
- 权限决定页签、板块和动作可见性；
- 权证清单按八类计算完整度，其他材料不计入；
- 支付凭证多文件选择、失败提示和上传成功刷新；
- 商品绑定显示精确来源文件，上传新版本后不自动切换；
- 保险与电池、估值与折旧、资本与分润的数据来源标签正确；
- 客户预览是动作，不再作为二级页签。

### 13.2 API 单元与集成测试

- 新权证枚举的 DTO 校验和标签映射；
- 批次版本号并发唯一；
- 多文件批次全部成功或全部失败；
- 八类权证强制 `customerVisible=false`；
- 支付凭证允许多文件和追加批次；
- 绑定只允许本车、有效、正确类型的图片；
- 新版本上传不改变绑定；
- 被引用文件归档/删除返回 409；
- 解除绑定后允许归档；
- Portal 仅在商品已发布且可见时返回原件；
- Portal 无法通过猜测文档 ID 读取其他车辆或未绑定权证；
- 原有保险附件客户可见测试保持通过。

### 13.3 端到端验收

使用现有可用车辆 `VEH20260731152647G5GV`：

1. 从车辆列表点击该车辆并进入独立详情 URL；
2. 刷新页面后保持当前页签；
3. 依次打开六个一级页签并验证对应数据；
4. 上传两份车辆采购支付银行回单，确认同一批次显示两个文件；
5. 再追加一份回单，确认历史文件仍有效；
6. 上传配置单和检测报告图片原件；
7. 在商品展示中分别绑定两份指定原件；
8. 客户预览在对应板块直接显示长图；
9. 上传新的检测报告版本，确认客户预览仍显示原绑定；
10. 尝试归档被引用版本，确认被阻止；
11. 主动改绑到新版本后确认预览更新，再解除旧版本保护；
12. 验证发票、车主信息、支付凭证等其他权证不能从 Portal 访问；
13. 从“待销售价复核”进入车辆，完成现有复核动作并在单车销售价历史中看到记录；
14. 验证现有保单、BaaS、折旧、估值、资本和分润动作没有回归。

## 14. 验收标准

1. 车辆详情不再使用大浮层，具有稳定 `/vehicles/[id]` URL；
2. 六个一级页签和已确认的二级分类完整落地；
3. 列表只保留“车辆列表”和“待销售价复核”，“销售价历史”进入单车详情；
4. 列表操作只保留详情，单车动作在详情上下文中可达；
5. 权证页展示八类清单，支付凭证支持多文件上传和继续追加；
6. 八类权证没有客户可见开关，API 也不能将其直接公开；
7. 配置单和检测报告图片原件可以绑定到商品对应板块，且不复制对象；
8. 绑定固定到精确文件版本，新版本不自动替换；
9. 被引用版本在解除绑定前不能归档或删除；
10. PDF 只在内部预览，不能作为商品原件绑定；
11. 详情首屏不预加载全部子域或原件长图；
12. 页签局部失败不影响其他页签；
13. 现有车辆状态、销售价、保险、BaaS、商品发布、估值、折旧、资本和分润规则保持不变；
14. 主要 Admin 桌面宽度下无横向页面溢出，宽表允许板块内横向滚动；
15. 原有 API 测试、新增 API 测试、Web 类型检查、Lint、构建和关键端到端验收全部通过。

## 15. 后续实施边界

实施计划应按以下顺序拆分，避免在一个超大任务中同时迁移全部 UI：

1. 路由壳、列表导航和共享摘要头；
2. 车辆概览及现有轻量模块迁移；
3. 权证枚举、批次上传、权限边界和权证页；
4. 商品原件绑定、受控 Portal 预览和商品展示重组；
5. 保险与电池页迁移；
6. 估值与折旧页迁移及销售价历史归位；
