# Field 现场拍摄与大文件上传设计

日期：2026-07-25

## 目标

优化 Field 车辆现场交接资料采集体验：

- 照片事项同时支持现场调用后置摄像头拍照，以及从相册/文件库选择。
- 视频事项同时支持现场调用后置摄像头录像，以及从相册/文件库选择。
- 图片单文件上限从 5MB 提升到 10MB。
- 视频单文件上限从 200MB 提升到 300MB。
- 大文件上传提供明确进度、取消、失败重试和友好错误。
- 延续现有原子“上传并绑定资料事项”语义，不产生可见孤立文件。

## 非目标

- 本轮不建设 OSS 客户端分片直传或断点续传。
- 不新增第三方上传依赖。
- 不改变交接资料清单、必传规则和资料审核状态机。
- 不改变 Field、Portal、Admin 的权限边界。
- 不改变客户异议、现场复检、客户重审和 Admin 处理流程。
- 不修改 Stage 2 PDF、电子签、交付确认、租赁或计费逻辑。

## 当前实现

Field 任务详情使用一个隐藏的 `input[type=file]`：

- 通过 `accept` 限定事项允许的媒体类型。
- 通过 `multiple` 控制是否允许一次选择多个文件。
- 没有 `capture` 属性，移动端是否展示摄像头入口由浏览器自行决定。
- 上传期间只显示加载状态，没有可读进度和取消入口。

当前大小限制：

- Web 图片：`5 * 1024 * 1024`
- Web 视频：`200 * 1024 * 1024`
- API 图片：`5 * 1024 * 1024`
- API 视频：`200 * 1024 * 1024`
- Multer 单文件上限：`200 * 1024 * 1024`

API 已使用磁盘临时文件承接上传，并由清理拦截器处理成功、校验失败、鉴权失败和异常路径。

## 方案选择

采用“原生双入口 + 可取消上传进度”方案。

不采用单一文件输入依赖系统选择器，因为 Safari、微信内置浏览器和 Edge 的入口展示不一致，现场人员不能稳定判断如何调用摄像头。

本轮不采用 OSS 分片直传。分片直传对 300MB 视频更具扩展性，但需要临时凭证、分片会话、废弃分片清理、最终绑定和权限审计，超出本次体验优化范围。

## Field 交互设计

### 照片事项

显示两个明确操作：

- `现场拍照`
- `从相册选择`

`现场拍照` 使用：

```html
<input type="file" accept="image/*" capture="environment">
```

每次现场拍照只接收一个文件。对允许多文件的损伤近照事项，现场人员可重复拍摄，文件累计绑定到同一事项。

`从相册选择` 不设置 `capture`，并继续根据事项的 `allowsMultiple` 设置 `multiple`。

### 视频事项

显示两个明确操作：

- `现场录像`
- `从相册/文件选择`

`现场录像` 使用：

```html
<input type="file" accept="video/*" capture="environment">
```

每次现场录像只接收一个文件。文件库入口不设置 `capture`。

### 兼容性降级

`capture` 是浏览器提示，不保证所有客户端都直接打开摄像头。对于不支持该属性或忽略该属性的客户端：

- 操作仍退化为系统文件选择器。
- 不阻断上传。
- 不自行实现 WebRTC 相机界面。

验收客户端包括：

- iPhone Safari
- 微信内置浏览器
- 桌面 Edge

### 操作状态

每个事项同一时间只允许一个上传批次：

- 上传期间禁用该事项的拍摄和选择入口。
- 显示当前文件名、上传百分比和已传/总大小。
- 提供取消按钮。
- 取消或失败后恢复入口，并提供重试。
- 已成功绑定的文件继续支持预览、下载、删除和替换。
- 资料锁定状态下不展示可操作的上传、删除和替换入口。

## 上传实现

### Web

将当前 Field 上传请求改为支持上传进度和取消的浏览器原生请求实现：

- 使用 `XMLHttpRequest` 上传 `FormData`。
- 使用 `xhr.upload.onprogress` 更新进度。
- 使用 `xhr.abort()` 取消请求。
- 沿用 Field 会话 Cookie，不读取或暴露会话令牌。
- 保持现有请求超时和用户可读错误语义。
- 不引入新依赖。

每个上传批次保持当前串行绑定语义。多文件选择时逐个调用原子上传接口：

1. Web 本地校验文件类型和大小。
2. 上传单个文件到对应资料事项。
3. API 校验、存储并在同一业务操作中绑定资料记录。
4. Web 刷新任务详情和 readiness。
5. 继续处理下一个文件。

前一个文件失败或取消后停止当前批次，已成功的文件保持已绑定状态，未上传文件不会继续静默提交。

### API

保留现有原子上传并绑定端点、Field 会话守卫、磁盘临时目录和清理拦截器。

调整限制：

- 图片：`10 * 1024 * 1024`
- 视频：`300 * 1024 * 1024`
- Multer 单文件硬上限：`300 * 1024 * 1024`

Multer 上限只负责阻止超过 300MB 的请求。业务服务仍按媒体类型执行更严格限制，因此 10MB 以上图片即使低于 Multer 上限也必须被 API 拒绝。

错误响应继续使用稳定、可读的中文信息：

- `图片不能超过 10MB。`
- `视频不能超过 300MB。`
- 不支持的媒体类型
- 会话失效
- 任务不可编辑
- 上传取消、网络超时或存储失败

任何失败路径不得返回对象存储 key、bucket、内部路径、Cookie 或 Field 会话信息。

## 部署约束

应用限制放开后，staging 和生产部署还必须满足：

- 反向代理请求体上限至少 320MB。
- 上传请求超时足以覆盖弱网下的 300MB 视频。
- API 容器临时目录具备单文件 300MB 及并发余量。
- OSS 上传超时大于 API 接收完整文件后的存储耗时。

建议把代理请求体上限设置为 320MB，而不是无限制。代理配置仍是最终防线，应用层继续执行 10MB/300MB 业务限制。

部署配置若由外部基础设施仓库管理，应在发布说明中明确前置操作；本仓库不为满足本功能而修改无关 compose 或生产配置。

## 清理与一致性

继续验证临时文件在以下路径均被清理：

- 上传并绑定成功
- 图片或视频超限
- 文件类型非法
- Field 会话无效
- 任务状态不可编辑
- OSS 或数据库异常
- 客户端主动取消连接

客户端取消不保证服务器立即收到结构化业务错误，因此清理必须依赖请求关闭/异常路径和现有统一清理拦截器，不能依赖 Web 再发清理请求。

## 测试设计

### Web 单元测试

- 照片事项渲染“现场拍照”和“从相册选择”。
- 视频事项渲染“现场录像”和“从相册/文件选择”。
- 拍摄输入包含 `capture="environment"`，文件库输入不包含 `capture`。
- 拍摄输入单文件，文件库入口遵循 `allowsMultiple`。
- 损伤近照支持重复拍摄和多文件累计。
- 10MB 图片通过本地校验，超过 10MB 被拒绝。
- 300MB 视频通过本地校验，超过 300MB 被拒绝。
- 上传进度、取消、失败重试和完成状态正确。
- 任务锁定时不存在可编辑入口。
- 页面不显示对象存储内部信息。

### API 单元与集成测试

- 10MB 图片通过，`10MB + 1 byte` 被拒绝。
- 300MB 视频通过，`300MB + 1 byte` 被 Multer 或服务校验拒绝。
- 10MB 以上图片不会因为 Multer 上限为 300MB 而被接受。
- 合法图片和视频上传后立即绑定正确事项。
- 成功、业务校验失败、鉴权失败和异常路径均清理临时文件。
- 取消连接或流中断不形成资料记录。
- 原有 Field 权限、版本检查和任务编辑状态约束保持有效。

### 浏览器人工验收

- Safari 的现场拍照和录像入口调用后置摄像头或合理降级。
- 微信内置浏览器无灰屏、无无限加载，两个入口均可用。
- Edge 合理降级为文件选择器，文件库上传可用。
- 9MB 图片成功，11MB 图片显示超限。
- 接近 300MB 的视频成功，超过 300MB 的视频显示超限。
- 大视频显示持续进度，可取消并重试。
- 取消或失败后资料数量不增加。
- 损伤近照可多次拍摄、删除、替换并通过复检。

## 成功标准

- 现场人员不需要依赖浏览器隐式菜单即可选择拍摄或文件库上传。
- 图片和视频的新大小上限在 Web、API 和部署入口一致生效。
- 300MB 视频上传期间有明确反馈，不表现为无期限加载。
- 失败或取消不会绑定资料，也不会留下未清理的临时文件。
- 现有 Field 闭环、客户异议复检和审计事件行为不回归。
