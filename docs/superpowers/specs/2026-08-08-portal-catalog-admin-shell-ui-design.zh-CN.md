# Portal 商品列表与 Admin 导航外壳 UI 优化设计

日期：2026-08-08

状态：已批准（2026-08-08）

## 1. 背景

本次调整解决两个相互独立、但可以在同一前端发布中验收的问题：

1. Portal 商品列表 `/portal/catalog` 沿用桌面横向列表结构，在微信内置浏览器等窄屏环境中出现标题、地址、标签和“查看详情”互相挤压，部分内容越出卡片；当前金额格式还会把以分为单位的 `1` 显示成 `¥0`。
2. Admin 的 `ProtectedShell` 让左侧导航与右侧内容跟随整个页面共同滚动；切换二级菜单时页面外壳重新挂载，受控 `openKeys` 先清空再从 `sessionStorage` 恢复，造成一级菜单重复收起、展开或播放展开动画。

用户已确认：Portal 采用视觉方案 A；Admin 采用局部修复方案，不在本次把所有后台页面迁移到共享 App Router Layout。

本次任务属于前端展示与交互重组，不改变既有流程、数据库模型或 API 合同。

## 2. 目标

### 2.1 Portal 商品列表

- 在 360px、390px 等手机宽度下形成稳定、可扫读且无横向溢出的商品卡片。
- 保留桌面端现有横向列表的信息密度和使用习惯。
- 移动端默认收起筛选区，把首屏空间优先留给商品。
- 使用客户可读的车型名称，避免把内部车型代码或重复品牌、年款暴露给客户。
- 正确显示以分为单位的最低月租，保留有效小数精度。
- 保留现有筛选、列表请求、商品详情导航和空状态行为。

### 2.2 Admin 导航外壳

- 左侧功能区与右侧内容区分别滚动，右侧长页面滚动不改变左侧导航位置。
- 点击二级菜单进入其他页面时，已经展开的一级菜单保持展开，不重播展开动作。
- 页面内导航、浏览器前进/后退和整页刷新后，菜单展开状态符合当前路由并尽量保留用户手动展开状态。
- 保留现有登录校验、权限过滤、退出登录、修改密码入口和移动端折叠侧栏行为。

## 3. 非目标

本次不包含：

- Portal 商品详情页、申请流程、订单流程或支付流程改造；
- 商品筛选 API、商品 DTO、数据库字段或 Prisma migration 改造；
- Admin 菜单信息架构、RBAC 权限、路由命名或菜单文案调整；
- 把所有 Admin 页面中的 `ProtectedShell` 删除并迁移到共享 Next.js Layout；
- 全站视觉主题、Ant Design 版本或响应式框架升级；
- 用关闭所有菜单动画来掩盖状态重置；
- 与本需求无关的既有测试或页面重构。

## 4. 现状与约束

### 4.1 Portal 现状

当前实现集中在：

```text
apps/web/src/app/portal/catalog/page.tsx
```

页面同时承担筛选状态、数据请求、导航和商品卡片展示。商品使用 Ant Design `List.Item`、`List.Item.Meta` 和 actions 组成桌面横向布局；大量展示样式为内联样式。窄屏时图片、文字、地址、标签和操作链接继续争用同一行宽度，因此产生溢出。

现有 Staging 样例已经提供可用于客户展示的字段：

```text
modelDefinition.customerDisplayName = NIO ES6 2024款
customerModelDisplayName = NIO/蔚来 ES NIO ES6 2024款 2024款
monthlyFeeFromAmount = 1
```

其中组合后的 `customerModelDisplayName` 存在重复；`monthlyFeeFromAmount` 的单位是分，当前零位小数格式把 1 分显示成了 0 元。

### 4.2 Admin 现状

当前外壳实现集中在：

```text
apps/web/src/components/protected-shell.tsx
```

各 Admin 页面分别包装 `ProtectedShell`，因此客户端切换路由时外壳可能重新挂载。`openKeys` 由组件控制，但持久状态只在 `useEffect` 后从 `sessionStorage` 恢复，首帧会经历空状态。外层 `Layout` 只设置最小高度，浏览器 body 承担滚动，所以 Sider 与右侧内容一起移动。

本次选择局部修复，原因是它能在单一外壳内解决已确认问题，改动面和回归面都明显小于迁移全站路由布局。

## 5. 总体设计

两个子项共享同一原则：保留数据和业务控制层，只整理展示边界与临时 UI 状态。

```text
Portal catalog page
  ├─ 筛选状态、请求、导航（保留）
  ├─ 响应式筛选容器（调整）
  └─ 商品卡片展示/格式化（拆分并测试）

ProtectedShell
  ├─ 登录、权限、用户操作（保留）
  ├─ 菜单展开状态缓存（调整）
  ├─ 菜单滚动位置缓存（新增 UI 状态）
  └─ 左右独立滚动布局（调整）
```

前端改动使用 CSS Module 承担响应式和外壳布局，避免继续扩大 JSX 内联样式。纯展示规则提取为小型函数或展示组件，使名称、标签、金额和菜单状态可以独立测试。

## 6. Portal 商品列表详细设计

### 6.1 页面职责

`page.tsx` 继续负责：

- 品牌、车型、车型代码和城市筛选状态；
- 调用现有 catalog API；
- loading、空状态和错误提示；
- 跳转商品详情及“我的入口”。

商品卡片只接收已取得的商品数据和详情导航动作，不自行发起请求。展示辅助层负责把原始字段转换成客户可读标题、事实项、标签和价格文本。

### 6.2 响应式断点与布局

以 `768px` 为移动端断点：

| 视口 | 筛选区 | 商品卡片 |
| --- | --- | --- |
| `> 768px` | 默认展开，保留当前桌面表单布局 | 保留桌面横向图片、信息、操作布局 |
| `<= 768px` | 默认收起，可点击展开 | 方案 A：图片在上，信息在下，底部价格与详情操作固定分列 |

移动卡片从上到下为：

1. 16:9 全宽封面图；
2. 客户展示标题，最多两行；
3. 上牌时间、里程等基础事实；
4. 所在地，单行省略；
5. 客户标签和必要事实标签，允许换行但不得撑破卡片；
6. 底部操作行：左侧价格，右侧“查看详情”。

图片使用 `object-fit: cover`。无图片时使用相同 16:9 占位区域，避免卡片高度和后续内容突然上移。卡片内容设置 `min-width: 0`，所有可能变长的文字都由明确的截断或换行规则约束。

桌面布局只做必要的展示规则修正，不改为移动卡片的纵向结构，避免本次任务扩大成桌面重设计。

### 6.3 筛选区

- 桌面端始终展示完整筛选表单。
- 移动端首次进入默认收起，显示“筛选”入口。
- 展开后仍使用同一组表单控件和同一套筛选状态，不复制第二份移动表单。
- 已有筛选条件时，收起态需要通过计数或“已筛选”状态提示用户当前结果受到条件限制。
- 提交筛选后允许保持当前展开状态；不因请求完成自动开合。
- 清空条件沿用现有筛选行为，不增加服务端参数。

实现可以使用语义化 `details/summary` 或等价的受控容器，但必须保证桌面端不会被折叠、键盘可操作，并避免在断点切换时创建两份表单状态。

### 6.4 客户展示标题

标题按以下优先级选择第一个非空值：

1. 商品显式配置的 `shortTitle`；
2. `modelDefinition.customerDisplayName`；
3. 现有兼容展示字段中经过清理的客户可读名称；
4. 品牌、车系、车型和年款组成的最小可读回退文本。

约束：

- 不把内部车型代码作为主标题；
- 不重复品牌、车型或“年款”；
- 兼容字段为空时不得显示 `undefined`、空括号或多余分隔符；
- 移动端最多两行，桌面端允许现有信息密度下的合理换行。

### 6.5 基础事实与标签

上牌时间、里程和所在地继续来自现有响应字段，只改变排列方式。缺失值使用统一回退文本或隐藏整项，不拼接残缺句子。

标签优先级：

1. 运营明确配置的客户标签；
2. 对客户有决策价值、但尚未在标题或基础事实中表达的信息；
3. 现有兼容标签。

同一标准化文本只展示一次。已经作为标题、所在地、上牌时间或里程展示的派生文本，不再重复生成标签。去重比较至少需要忽略首尾空格和连续空白差异。

### 6.6 金额格式

`monthlyFeeFromAmount` 按“分”转换为“元”，不得先四舍五入为整数：

| 原始值 | 展示 |
| ---: | --- |
| `1` | `¥0.01 / 月起` |
| `100` | `¥1 / 月起` |
| `12345` | `¥123.45 / 月起` |
| `null` / 缺失 | `月租审核后确认` |

有效小数最多两位，整数金额不显示无意义的 `.00`。零值如果是合法明确的业务值则显示 `¥0 / 月起`；只有缺失值使用待确认文案。

### 6.7 交互与异常状态

- 点击“查看详情”沿用现有详情路由。
- 图片加载失败时切换到占位内容，不让破图图标改变布局。
- 商品数据为空时沿用现有空状态。
- API 失败时沿用现有错误提示和重试方式。
- 超长标题、超长地址、标签过多、无图片、无价格均不得造成水平页面滚动。

## 7. Admin 导航外壳详细设计

### 7.1 独立滚动结构

Admin 外壳占满当前视口并关闭 body 级内容滚动：

```text
Admin shell: height 100dvh, overflow hidden
  ├─ Sider: full height, flex column
  │    ├─ Brand/header: flex none
  │    └─ Menu viewport: flex 1, min-height 0, overflow-y auto
  └─ Right column: full height, flex column, overflow hidden
       ├─ Header: flex none
       └─ Content viewport: flex 1, min-height 0,
                              min-width 0, overflow-y auto
```

使用 `100dvh` 并提供 `100vh` 回退。`min-height: 0` 用于允许 flex 子项在固定视口内收缩并真正产生内部滚动；`min-width: 0` 防止右侧宽表或长文本把整个外壳撑宽。

预期行为：

- 滚动右侧 Content 时，品牌区和左侧菜单位置不变；
- 左侧菜单项目超过视口时，仅菜单容器自身滚动；
- 顶部 Header 保持可见；
- 允许具体业务板块在自身需要时提供局部横向滚动，但页面外壳不产生水平滚动。

### 7.2 菜单展开状态模型

菜单展开状态采用“模块内存优先、会话存储兜底、当前路由强制补齐”的策略：

```text
initialOpenKeys
  = valid(moduleMemory.openKeys)
  ?? valid(sessionStorage.openKeys)
  ?? []

renderedOpenKeys
  = merge(initialOpenKeys, ancestorsOf(currentPath))
```

规则：

1. 模块级内存缓存使客户端路由导致的 `ProtectedShell` 重新挂载可以在首帧同步取得上一次状态，不经历空数组过渡。
2. `sessionStorage` 支持整页刷新后恢复同一浏览器标签页中的状态。
3. 当前路由的所有祖先一级菜单始终被合并进展开集合，保证当前二级菜单可见。
4. 路由变化只补齐祖先，不清除用户手动展开的其他一级菜单。
5. 只有用户实际点击一级菜单的展开/收起控件时，`onOpenChange` 才改变展开集合。
6. 点击叶子二级菜单只负责导航，不直接清空或重建 `openKeys`。
7. 缓存值需要按当前可见菜单 key 白名单过滤；JSON 损坏、类型错误或已经不存在的 key 直接忽略。
8. 用户权限变化后，不可见菜单 key 不得继续进入受控状态。

数组合并需要稳定去重，避免无意义的状态写入和重复渲染。状态每次有效变化时同步更新模块内存，并写入 `sessionStorage`；存储失败不能阻止菜单使用。

### 7.3 菜单滚动位置

左侧菜单容器的 `scrollTop` 作为纯 UI 状态缓存：

- 导航前或滚动时记录到模块内存；
- 组件重新挂载后，在菜单元素可用时恢复；
- 同一标签页整页刷新时可选择从 `sessionStorage` 恢复；
- 恢复值超出当前滚动范围时由浏览器自然截断；
- 移动端折叠/展开或权限变化后恢复失败不视为业务错误。

至少必须保证客户端二级菜单切换不会把左侧菜单跳回顶部。持久化只保存数值，不保存任何业务或身份信息。

### 7.4 路由与移动端行为

- 菜单选中项继续由当前 pathname 推导，不建立第二份选中状态。
- 浏览器前进/后退触发 pathname 变化时，补齐新路由祖先并保留其他有效展开项。
- 整页刷新先从缓存同步初始化，不出现“全部收起后再展开”的可见过程。
- 现有 Sider 折叠状态和小屏行为保持可用；若折叠态不显示完整子菜单，重新展开后仍恢复有效的展开集合。
- 登录失效、登出和无权限行为不因菜单缓存而改变；无权限菜单仍由现有权限过滤控制。

## 8. 文件与组件边界

实施计划可按以下边界落地，最终文件名可服从仓库现有命名规范：

```text
apps/web/src/app/portal/catalog/page.tsx
  保留查询、筛选和导航编排

apps/web/src/app/portal/catalog/*.module.css
  Portal 筛选与商品卡片响应式布局

apps/web/src/app/portal/catalog/*presentation*.ts(x)
  标题、标签、价格等纯展示规则或商品卡片

apps/web/src/components/protected-shell.tsx
  保留认证/权限编排，接入菜单状态辅助层

apps/web/src/components/protected-shell.module.css
  视口外壳与左右独立滚动

apps/web/src/components/*menu-state*.ts
  菜单状态校验、合并与缓存边界
```

不要求为了拆文件而拆文件。如果纯函数较少且 `page.tsx` 保持可读，可以放在邻近 helper 文件；但响应式样式不得继续全部堆在 JSX 内联对象中。

## 9. 数据与状态流

### 9.1 Portal

```text
筛选表单
  → 现有筛选状态
  → 现有 catalog API 请求
  → 原始商品列表
  → 展示辅助函数（标题/事实/标签/金额）
  → 桌面或移动 CSS 布局
  → 现有详情导航
```

整个链路不新增网络请求，不修改请求参数，也不把响应式状态发送给服务端。

### 9.2 Admin

```text
pathname + 可见菜单树 + 缓存 openKeys
  → 过滤无效 key
  → 合并当前路由祖先
  → Ant Design Menu controlled openKeys
  → 用户实际开合
  → 模块内存 + sessionStorage
```

菜单状态和滚动位置都属于浏览器标签页内的临时 UI 状态，不写入数据库，不进入审计日志。

## 10. 可访问性与兼容性

- 移动筛选入口必须可通过键盘聚焦和操作，并有清晰的展开状态。
- 商品图片提供合理替代文本；装饰性占位不重复朗读无意义内容。
- “查看详情”保持明确的链接或按钮语义和可触达区域。
- 文本截断不能作为隐藏关键业务状态的手段；价格和主要操作始终完整可见。
- 独立滚动区域保持浏览器原生滚动，不劫持滚轮或触摸事件。
- 不依赖仅 Chromium 支持且无回退的尺寸能力；`100dvh` 需要 `100vh` 回退。

## 11. 测试策略

### 11.1 Portal 自动化测试

- 客户标题优先级：`shortTitle`、客户车型名、兼容回退依次生效。
- 内部车型代码不进入主标题。
- 重复品牌、车型、年款和重复标签被去除。
- 价格按分精确格式化：1 分、整元、含角分、0 和缺失值。
- 缺少图片、地址、里程或标题字段时返回稳定回退。
- 筛选状态与请求参数保持现有合同。

### 11.2 Admin 自动化测试

- 初始状态优先使用有效模块内存，其次使用有效 `sessionStorage`。
- 损坏 JSON、非字符串数组、未知菜单 key 被忽略。
- 当前路由祖先被补齐，其他手动展开菜单不被清空。
- 叶子菜单导航不修改 `openKeys`。
- 用户主动开合后模块内存与会话存储同步。
- 权限过滤后无效 key 被移除。
- 外壳和滚动容器具有约定的布局类或样式行为。

### 11.3 浏览器验收

Portal：

1. 在 360px 和 390px 视口打开 `/portal/catalog`，页面无水平滚动条。
2. 筛选默认收起，可展开、筛选、再次收起；有筛选条件时收起态有提示。
3. 检查超长标题、超长所在地、多标签、无图片和无价格样例。
4. 1 分显示为 `¥0.01 / 月起`，整元不显示无意义小数。
5. 点击“查看详情”进入原商品详情。
6. 在桌面宽度检查原横向列表无明显回归。

Admin：

1. 打开一个右侧内容足够长、左侧菜单也可滚动的页面。
2. 滚动右侧到底部，左侧品牌区和菜单滚动位置不变化。
3. 单独滚动左侧菜单，右侧内容位置不变化。
4. 展开一个一级菜单，依次点击其中不同二级菜单；一级菜单不收起、不重播展开。
5. 手动同时展开多个一级菜单，切换二级页面后仍保持有效展开状态。
6. 使用浏览器前进、后退和整页刷新，当前路由的祖先菜单可见，缓存损坏时也能安全回退。
7. 检查移动端侧栏折叠/展开、退出登录和修改密码入口无回归。

## 12. 验收标准

1. Portal 在 360px、390px 及桌面视口均无页面级横向溢出。
2. 移动商品卡片符合方案 A：16:9 图片在上，信息在下，价格和详情操作位于稳定底部行。
3. 移动筛选默认收起，且不复制第二套筛选状态。
4. 客户标题不显示内部车型代码，不出现已知重复品牌/车型/年款。

## 14. 发布、回滚与风险控制

- 两项改动均随 Web 镜像发布，无数据库部署顺序要求。
- 发布前在 Staging 使用微信内置浏览器或等效窄屏环境完成 Portal 验收，并使用真实长页面完成 Admin 双滚动验收。
- 回滚只需要回滚 Web 镜像；菜单缓存是客户端临时状态，旧版本会忽略新增 key。
- CSS 固定视口的主要风险是移动浏览器动态地址栏高度，因此采用 `100dvh` 加 `100vh` 回退并在实际浏览器验证。
- 菜单状态的主要风险是陈旧或越权 key，因此恢复前必须与当前权限下的可见菜单树求交集。
- Portal 的主要风险是字段组合兼容性，因此格式化层必须覆盖真实 Staging 样例和缺失字段样例。
