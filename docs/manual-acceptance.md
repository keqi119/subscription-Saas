# 人工验收总清单

本文档用于 Stage 9B 发布准备收口。验收按业务主线组织，而不是只按页面罗列。

本手册是 `docs/release-checklist.md` 的人工验收部分。发布前必须结合 release checklist 使用，并将验收结论回填到 release 记录。

通用规则：

- 验收前执行 `pnpm prisma:seed`，然后退出并重新登录。
- 默认 seed 只提供 baseline master data，不提供完整流程数据。
- 复杂链路可人工创建，也可在后续 Stage 9C 使用 scenario seed。
- 每个关键动作都应抽查 AuditLog。

## Stage 9C 场景 Seed 与 Smoke

可在开发 / 验收环境执行：

```powershell
pnpm seed:scenario cleanup
pnpm seed:scenario mainline
pnpm seed:scenario residual
pnpm smoke:api
```

主线场景输出：

```text
.tmp/scenarios/mainline.json
```

残值场景输出：

```text
.tmp/scenarios/residual.json
```

验收时可从 JSON 中读取 `customerId`、`applicationId`、`vehicleId`、`curveId`、`forecastId`、`forecastPointId`、`valuationReviewId` 等标识，并在对应页面或详情 API 中定位数据。`mainline` 第一版只创建客户、进件、专用车辆和 active subscription plan 引用，报价、订单、合同、账单仍从进件继续人工推进。`residual` 第一版创建市场样本、残值曲线、单车预测和待审批估值复核。

可选按场景追加 smoke：

```powershell
pnpm smoke:mainline
pnpm smoke:residual
```

如需指定输出文件：

```powershell
$env:SMOKE_SCENARIO_FILE=".tmp/scenarios/mainline.json"
pnpm smoke:api
```

## 1. 登录与权限刷新

入口页面：

- 登录页
- 系统管理
- `/api/auth/me`

前置数据：

- 已执行 seed。
- 默认管理员账号存在。

操作步骤：

1. 使用 `admin / Admin@123456` 登录。
2. 打开系统管理，查看用户、角色、权限、菜单。
3. 执行一次 seed 后退出并重新登录。
4. 使用低权限账号抽查菜单差异。

预期结果：

- ADMIN 可登录并看到完整菜单。
- `/api/auth/me` 返回用户、角色、权限、菜单。
- 权限变更后重新登录才生效。

关键不允许行为：

- 未授权用户看到受控菜单。
- 权限变更后旧 token 继续使用过期权限。

## 2. 客户 / 线索

入口页面：

- `/customers`

前置数据：

- seed 创建干净客户 leads，或人工新增客户。

操作步骤：

1. 查看客户列表。
2. 新增或选择一个 lead。
3. 更新客户基础信息。

预期结果：

- 客户编号、姓名、联系方式等字段正常显示。
- 客户修改写入审计日志。

关键不允许行为：

- 无 `customer:manage` 权限仍可编辑客户。

## 3. A 线自助进件

入口页面：

- `/applications`
- `/applications/:id`

前置数据：

- 存在客户 lead。
- 存在启用产品、订阅套餐和可用车辆。

操作步骤：

1. 创建 `SELF_SERVICE` 进件或通过后续 scenario seed 创建。
2. 填入意向车辆、意向订阅套餐、期数和车辆基础费。
3. 查看进件详情中的意向快照、资料区和押金状态。

预期结果：

- A 线只创建 Application，不直接创建正式订单。
- 押金状态为待确认。
- 客户意向方案仅作为审核前快照。

关键不允许行为：

- 首次提交即生成正式 `SubscriptionOrder`。
- 客户自由组合产品组件包。

## 4. B 线销售辅助进件

入口页面：

- `/customers`
- `/applications`
- `/applications/:id`

前置数据：

- 存在客户和基础产品/车辆数据。

操作步骤：

1. 销售创建客户和销售辅助进件。
2. 提交资料。
3. 后台进入审核。

预期结果：

- B 线仍沿用后台进件、风控、报价、订单、合同路径。

关键不允许行为：

- B 线报价路径被 A 线改造破坏。

## 5. 审核

入口页面：

- `/applications`
- `/applications/:id`
- `/risk/deposit-rules`

前置数据：

- A/B 线进件已提交。
- 押金规则存在。

操作步骤：

1. 完成资料审核。
2. 完成信用/风控审核。
3. 完成产品匹配审核。
4. 完成车辆库存审核。
5. 确认最终方案和最终押金。

预期结果：

- 审核状态逐项更新。
- 最终押金来自客户等级、押金规则和风控结果。
- 审核动作有审计日志。

关键不允许行为：

- 未审核通过就生成正式订单。
- 修改最终押金没有记录。

## 6. 报价

入口页面：

- `/applications/:id`
- `/quotes`
- `/quotes/:id`

前置数据：

- 进件已审批通过。
- 存在 `AVAILABLE` 且销售价有效的车辆。
- 存在启用的 `SubscriptionPlan`。

操作步骤：

1. 在进件详情选择车辆和订阅套餐。
2. 输入车辆基础费。
3. 生成报价。
4. 查看报价详情。
5. 确认报价。

预期结果：

- 车辆基础费上限基于 `currentSalePriceAmount` 计算。
- 套餐总价可高于车辆基础费上限。
- 报价保存车辆、套餐、押金快照。
- 报价确认后车辆锁定为 `RESERVED`。

关键不允许行为：

- 使用 `purchasePriceAmount` 计算报价上限。
- 创建报价时即锁车。

- `/orders`

- 同一车辆被重复锁定给多个活跃订单。

- `/billing/monthly-rent`
- 订单详情财务区

1. 执行交付准备。

## 19. 资产经营分析

入口页面：

- `/reports/asset-profitability`

前置数据：

- 车辆有采购价、当前销售价、订单、账单和成本参数。

操作步骤：

1. 查看资产经营汇总。
2. 查看车辆列表。
3. 打开单车详情。
4. 查看收益试算。
5. 导出 CSV。

预期结果：

- `purchasePriceAmount` 用于成本和收益率。
- `currentSalePriceAmount` 仅作为当前估值/报价口径。
- ROA/ROE 是经营分析试算，不是正式会计报表。

关键不允许行为：

- 把押金计入经营收入。
- 把残值敏感性覆盖主 ROE。

## 21. 残值曲线

入口页面：

- `/residual-market` 的残值曲线 Tab

前置数据：

- 有有效市场价格样本。

操作步骤：

1. dryRun 生成曲线。
2. 正式生成草稿曲线。
3. 启用曲线。
4. 归档曲线。

预期结果：

- dryRun 不落库、不写审计。
- 正式生成创建曲线和曲线点。
- 启用新曲线会替代同维度旧曲线。

关键不允许行为：

- 曲线生成自动覆盖车辆当前销售价。

## 22. 单车残值预测

入口页面：

- `/vehicles` 车辆详情残值预测区块

前置数据：

- 车辆有初次上牌日期、品牌、车型。
- 有匹配的生效残值曲线。

操作步骤：

1. dryRun 预测。
2. 正式生成预测。
3. 查看预测点。
4. 人工采用一个支持的预测点。

预期结果：

- 预测点包含当前、6、12、24、36 月等 horizon。
- 人工采用只记录 adopted amount，不修改车辆当前销售价。

关键不允许行为：

- 预测生成或采用预测点写 `VehicleSalePriceHistory`。

## 24. 估值复核

入口页面：

- 车辆详情残值预测区块
- `/vehicle-valuation-reviews`

前置数据：

- 有单车残值预测点。

操作步骤：

1. 从支持的预测点发起估值复核。
2. 在工作台查看待审核复核。
3. 审核通过一条复核。
4. 新建复核并分别拒绝、取消。
5. 查看销售价历史。

预期结果：

- 发起、拒绝、取消不修改车辆当前销售价。
- 审核通过才更新 `Vehicle.currentSalePriceAmount`。
- 审核通过写 `VehicleSalePriceHistory.reviewType = RESIDUAL_FORECAST_ADOPTION`。

关键不允许行为：

- 其他残值链路动作写当前销售价或销售价历史。

## 26. 审计日志抽查

入口页面：

- `/system/audit-logs`

前置数据：

- 已执行客户、进件、报价、订单、合同、账务、车辆、残值、估值复核等关键动作。

操作步骤：

1. 按操作人筛选。
2. 按模块筛选。
3. 抽查关键 entityId 和快照。

预期结果：

- 关键 mutation 有审计日志。
- dryRun、GET 查询和 CSV export 不应写业务审计。

关键不允许行为：

- 估值复核审核通过无法追溯到 review、vehicle、forecast point 和 sale price history。
