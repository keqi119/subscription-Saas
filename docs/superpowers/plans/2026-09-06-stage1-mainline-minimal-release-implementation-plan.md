## 3. R 线收敛约束，不扩建发布平台

R1–R4 小计划必须遵守以下共享输入，不得各建一份字段权威：

- **唯一身份**：已有可信 CI 的 `build-proof.v1`。人工 manifest 只引用其 digest。删除另造 bundle 的设计；本地构建永久不可提升，CI 不可用时停止最终候选。
- **固定信任**：仓库固定 `release/contracts/manual-stage1-profile.v1.json`，公钥指纹/目标/命令策略/固定档案位置纳入 repository contract 和真实 build proof。profile 不引用未来 proof；CLI 不接受 profileFile、archiveRoot、trustRoot 等选择项或环境覆盖。
- **真实验签**：启动方实际验证 GitHub attestation 及固定 signer/source，再做结构绑定；不接受调用方自己声明 verified。新入口须进入 `RELEASE_GATE_ENTRY_POINTS` 和契约清单。
- **一次建立**：独立批准 key 生成/owner-only 保管、撤销消费台账、独立加密备份、恢复读回，再审查非秘密 profile 并通过 CI 固化。不是本轮生成密钥，也不建立云/本地 KMS 服务。
- **一种授权**：人工 launch authorization 使用互斥 stage 和单 capability；观察、来源导出、副本还原/脱敏/扫描、候选使用/命令执行各自独立凭证/operationId/记录。DDL 和业务 DML 不混合。
- **具体数据边界**：决策已选专用 WSL2 + 一次性 LUKS2。guest swap、宿主分页/转储、全部临时路径、备份排除、崩溃和销毁为获取数据的硬门槛，不接受“本地已加密”一句带过。
- **真实执行**：复用现有 handler、锁、事务、CAS、角色隔离；Runner 当前不能零改动直接当本地可信入口。先真实 migrate/verify 竖切，再扩大到必需命令，不批量迁出/升版无关命令。
- **无循环**：现有三镜像构建先于候选使用，不再添加构建前快照依赖。旧 Task 17B/I15B 延期；旧 qualification 或外部 final evidence 不拼接。
- **结果不是批准**：操作批准不能代替完成证据；失败/UNKNOWN 留存，只按同幂等键核对。最终签字只适用指定 Staging，不冒充旧 full-RC。

这些是审查约束，不是已实现的接口。R 小计划不得含“必要时修改”这种无边界施工指令；若需要代码，须先列出实际入口、字段、失败断言、文件所有权和提交路径。

5. R4/A3 按真实环境操作逐项批准；旧 Task 6/29R/30/I 不自动恢复。
