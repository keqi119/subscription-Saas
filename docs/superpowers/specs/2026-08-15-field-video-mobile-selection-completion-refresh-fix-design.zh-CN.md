# 现场车辆环绕视频移动端选取与完成态刷新修复设计

日期：2026-08-15
状态：已确认

## 1. 背景与实测结论

车辆环绕视频的服务端分片上传、OSS 合并、清晰度校验和资料绑定链路已经能够稳定处理大文件。PC 端实测约 `216.2 MB` 的视频可完成全部 `28/28` 个分片并正常打开；移动端实测约 `157.8 MB` 和 `188.9 MB` 的视频也能完成。

本轮存在两个相互独立的问题：

1. iPhone 微信内置浏览器从相册选择约 `226.9 MiB` 视频时，相册导出过程在文件交给网页前中断。此时 API 没有收到创建会话请求，资料项仍为 `0` 个文件。这不是 API、Nginx 或 OSS 上传超时。
2. 视频实际完成资料绑定后，最后一次上传会话查询仍按“新增或替换资料”重新校验容量和旧文件有效性。首次上传因此可能误报“该交付证据项只允许关联一个文件”，替换上传可能误报“待替换的交付资料文件不存在或已失效”。前端收到错误后不再刷新资料详情，返回列表再进入才显示实际成功结果。

## 2. 目标与范围

本轮目标：

- 保持服务端单个视频最高 `300 MiB` 的既有能力。
- PC 端继续使用现有文件选择入口，不新增操作步骤。
- 移动端为相册视频和大视频提供明确、简单的双入口。
- 文件一旦交给网页，先建立可恢复会话，再读取视频分片。
- 视频完成后立即刷新资料卡，不再把成功结果显示为失败。

本轮不修改数据库结构、视频清晰度标准、证据资料单文件规则、OSS 存储策略或交接流程。

## 3. 移动端上传交互

车辆环绕视频在移动端点击“资料上传”后显示两个操作：

1. **从相册选择（不超过 200 MB）**：用于常规视频，保留当前便捷路径。
2. **从文件选择（200–300 MB）**：提示现场人员先把大视频保存到 iPhone“文件”，再从文件选择器上传，以绕过微信相册的大文件导出阶段。

资料卡常驻说明调整为：

> 请使用手机系统相机以 720p 或更高画质录制完整车辆环绕视频。200 MB 以内可从相册选择；超过 200 MB 请先保存到手机“文件”后上传。单个视频不超过 300 MB。

若选择器返回空文件或被系统中断，页面保留资料卡并显示明确提示，不创建失败资料，也不显示虚假进度。桌面端入口和操作保持不变。

## 4. 上传会话与恢复指纹

Web 根据文件名、MIME、大小和最后修改时间生成恢复指纹。生成指纹不读取视频二进制内容，因此文件成功交给网页后，可以先创建服务端会话，再逐片读取并上传。

恢复指纹只用于同一资料项的未完成会话与重新选择文件匹配，不承担文件内容完整性校验。每个分片仍独立计算 SHA-256，服务端继续校验分片大小和哈希。

## 5. 完成态授权与页面刷新

上传会话状态查询只执行以下只读授权：

- 当前现场手机号仍可访问该交接任务；
- 会话属于请求中的任务和资料项；
- 资料项类型为车辆环绕视频。

状态查询不得再次执行资料容量校验，也不得要求创建会话时冻结的替换目标仍为有效文件。新增/替换目标、单文件容量和任务可编辑性校验仍只用于创建会话、上传分片、请求完成、重试和取消等变更操作。

当状态变为 `COMPLETED` 时，Web 清除恢复提示、刷新任务详情和资料清单、显示成功提示，并解除资料上传锁。刷新失败只能提示“资料已上传，请刷新查看”，不得把已完成上传改写为处理失败。

## 6. 错误处理

- 相册在文件交给网页前中断：提示改用“从文件选择”，服务端无残留会话。
- 文件交给网页后网络或页面中断：保留服务端会话和恢复卡片，重新选择同一文件后继续缺失分片。
- 完成后旧替换文件归档：状态查询仍返回 `COMPLETED`。
- 真正的资料容量或替换目标冲突：只在新建/变更请求时返回，并保留原有资料。

## 7. 验收标准

1. PC 端可上传 `200–300 MiB` 视频，完成后当前页面立即显示 `1 个文件` 和“已上传”。
2. 移动端车辆环绕视频资料卡提供“从相册选择”和“从文件选择”两个入口，文案明确 `200 MB` 分流建议。
3. 首次上传完成后不再出现“只允许关联一个文件”。
4. 替换上传完成后不再出现“待替换文件不存在或已失效”。
5. 完成后无需返回任务列表，资料卡自动刷新并可预览视频。
6. 相册未能返回大视频时，资料仍为 `0` 个文件且页面给出改用文件入口的提示。
7. API/Web 单元测试、类型检查和 Prisma 校验通过；本轮没有新增迁移。
