# Stage 10D-C4-C Enterprise Seal Policy Engine MVP Implementation

Stage 10D-C4-C implements the provider-free enterprise seal policy MVP above the existing B5 signing engine.

This stage does not call Fadada, generate sign URLs, execute signing, mutate Contract / Order, touch payment logic, create a migration, change Prisma schema, seed data, or deploy production.

## Scope

Implemented MVP:

```text
SignaturePolicyEngine.evaluate(input)
SignaturePolicyEngine.resolve(customer, contract, context)
SignaturePolicyEngine.compile(input) -> SigningPlan
SigningPlan compiler and hash helper
ApprovedSigningPlanRef metadata contract for B5
policy evaluation audit summary
plan generation audit summary
```

Not implemented in this stage:

```text
EnterpriseSeal persistence
SealAuthority persistence
SignaturePolicy persistence
SigningPlan persistence
Admin C4 APIs
Fadada enterprise seal provider APIs
mandatory C4 enforcement before B5
```

Those remain follow-up C4 stages.

## Policy Rules

The MVP policy engine is pure and deterministic. It has no Prisma, Fadada, B5, audit-write, Date.now, or production runtime dependency.

Current rules:

```text
customer.realNameStatus must be VERIFIED
customer.status must be ACTIVE
contract.status must be PENDING_SIGN
policy must be ACTIVE
required seal must be ACTIVE
policy.defaultSealId must match selected seal
actor must have REQUEST_USE or AUTO_USE authority
two-person authority returns REQUIRE_APPROVAL
```

Possible decisions:

```text
ALLOW
DENY
REQUIRE_APPROVAL
REQUIRE_ONBOARDING
REQUIRE_REALNAME
REQUIRE_SEAL_AUTHORITY
REQUIRE_POLICY_SELECTION
```

## SigningPlan MVP

`compileSigningPlan` creates an immutable provider-neutral plan:

```text
planId
version = 1
hash = sha256(canonical payload)
constraints
steps
```

The hash is reproducible from canonical JSON and changes when semantic execution inputs change, such as seal selection or step order.

MVP steps:

```text
1. CUSTOMER_SIGN
2. ENTERPRISE_SEAL, when the policy requires an enterprise seal
```

The plan does not include full customer ids, provider seal ids, provider raw responses, sign URLs, app secrets, or PII.

## C4 -> B5 Contract

B5 remains the execution engine. It does not compute policy.

`ESignService.createTaskForContract` now accepts an optional `ApprovedSigningPlanRef`. When present, B5 copies only policy metadata into `ContractESignTask.requestSnapshot`:

```text
signingPlanId
policyId
planHash
executionMode
stepSummary
```

The provider-facing signer list remains generated by B5's existing customer signing path in this MVP. Enterprise seal execution is not enabled by this stage.

Legacy behavior remains:

```text
createTaskForContract without ApprovedSigningPlanRef behaves as before
C4 plan reference is optional
C4 mandatory enforcement is not enabled
```

## Audit Boundary

Added pure audit summary helpers:

```text
createPolicyEvaluationAuditLog
createSigningPlanGenerationAuditLog
```

They return masked summaries only. They do not write audit rows by themselves.

Masked / excluded:

```text
full customer id
providerSealId
provider customer id
signUrl
provider raw response
PII
app secret
```
