# Golden Path 最终车辆确认与 Portal 我的资料导航修复设计

日期：2026-08-13

## 1. 背景与根因

本轮处理两个已由 staging 人工验收确认的问题。

1. `FINAL_VEHICLE_ALLOCATION` 是批准的 Golden Path 三个人工决策之一，必须保留审计记录；但当前 Admin 页面只提供空白车辆 UUID 输入框。A 线进件已经保存意向车辆、软锁车辆和最终车辆，运营人员不应重复复制 UUID。
2. Portal 已经在 `/portal/me` 实现姓名、身份证、省市区、详细地址和紧急联系人维护，在 `/portal/materials` 实现证件材料管理；但 Portal 首页“我的资料”仍跳转 `/portal/materials`，导致用户误以为基本资料维护能力不存在。

两个问题都属于页面投影与导航错误。现有车辆分配服务、客户资料 API、数据库字段和迁移均可复用。

## 2. 目标

- 保留一次 `FINAL_VEHICLE_ALLOCATION` 人工决定及其审计记录。
- A 线最终车辆与软锁车辆一致时，显示可读车辆信息并一键确认，不展示或要求输入车辆 UUID。
- 不改变最终车辆时，不增加最终方案版本，也不要求客户再次确认。
- 将 Portal“我的资料”统一呈现为“基本资料”和“证件材料”两个页签。
- Portal 首页点击“我的资料”默认进入“基本资料”。
- 保留 `/portal/me` 和 `/portal/materials` 现有路由兼容性及 `redirect` 返回地址。

## 3. 非目标

- 不取消 `FINAL_VEHICLE_ALLOCATION` 人工决策。
- 不改变车辆锁定、释放、换车和订单创建领域规则。
- 不新增数据库字段或迁移。
- 不重做客户资料 API、附件上传 API 或行政区数据。
- 不在本轮建设新的车辆检索、换车审批或车队自动分配能力。

## 4. 最终车辆确认设计

### 4.1 Admin Journey 投影

Admin Journey 的 Application 投影补充以下只读事实：

- `applicationSource`
- `finalVehicleId`
- `finalPlanSnapshot`
- 现有 `softReservedVehicleId`

前端从 `finalPlanSnapshot.vehicleSnapshot` 提取车辆编号、品牌/车型、车牌号和 VIN。缺少某一展示字段时显示 `-`，但提交依据始终使用服务端返回的 `finalVehicleId`，不得从展示文本反推 UUID。

### 4.2 A 线同车确认

当满足以下条件时进入“一键沿用”模式：

- `applicationSource = SELF_SERVICE`
- `finalVehicleId` 非空
- `finalVehicleId = softReservedVehicleId`
- Journey 当前步骤为 `FINAL_VEHICLE_ALLOCATION`

页面显示“已软锁车辆”卡片和可读车辆信息，主按钮为“确认沿用已软锁车辆”。点击后使用隐藏的 `finalVehicleId` 调用现有车辆分配接口。

服务端现有幂等规则继续负责最终校验：车辆必须仍由该 Application 软锁、状态为 `REVIEW_RESERVED`、不存在占用订单且最终方案事实没有变化。成功后将车辆审核状态置为通过、完成当前人工任务并推进 Journey。

### 4.3 其他情形

- 若已有 `finalVehicleId`，但不属于 A 线同车场景，显示“最终车辆”及可读信息，按钮为“确认最终车辆”。
- 若 `finalVehicleId` 缺失，页面不得要求填写裸 UUID；显示“最终方案缺少车辆，请返回最终方案步骤选择车辆”的阻断提示，不调用分配接口。
- 本轮不新增换车入口。需要换车时仍通过最终方案决定流程修改车辆；若商业事实变化，继续沿用现有“生成新版本并要求客户重新确认”的规则。

### 4.4 错误与并发

- 车辆不再可用时展示 API 返回的业务错误，不在前端伪造成功。
- Journey 版本冲突仍使用现有 `runJourneyMutation` 刷新最新状态。
- 按钮提交期间禁用重复操作。

## 5. Portal 我的资料设计

### 5.1 双页签导航

新增复用的“我的资料”页签导航：

- 基本资料：`/portal/me`
- 证件材料：`/portal/materials`

两个现有页面顶部均展示相同页签，当前路由决定选中状态。切换页签时保留合法的 `redirect` 查询参数，使客户保存资料或上传材料后仍能返回原商品或申请页面。

### 5.2 首页入口

Portal 首页“我的资料”改为指向 `/portal/me`。客户首先看到以下自助维护字段：

- 省、市、区县
- 详细地址
- 紧急联系人姓名
- 紧急联系人手机号

证件材料通过同一页面区域内的“证件材料”页签进入，避免用户把“资料”误解为只有附件。

### 5.3 兼容性

- 外部或历史链接访问 `/portal/materials` 时仍直接打开证件材料页签。
- 商品预检因基本资料缺失时继续跳转 `/portal/me`。
- 因证件材料缺失时继续跳转 `/portal/materials`。
- 登录失效后的回跳目标保持当前页面及必要查询参数。

## 6. 数据与安全边界

- 不在浏览器新增或缓存完整身份证号、车辆内部 UUID 以外的敏感信息。
- UUID 只作为已由后端投影返回的提交参数，不作为运营人员输入项。
- 资料保存仍由 `/portal/profile` 的服务端事务和完整性校验负责。
- 附件上传、预览和归档权限保持不变。

## 7. 测试与验收

### 7.1 自动化测试

1. A 线同车 Journey 渲染可读车辆信息及“确认沿用已软锁车辆”，不渲染车辆 ID 输入框。
2. 缺少 `finalVehicleId` 时渲染阻断提示且不提供确认按钮。
3. Admin Journey API 投影包含本轮所需只读车辆事实。
4. Portal 首页“我的资料”指向 `/portal/me`。
5. `/portal/me` 和 `/portal/materials` 都显示“基本资料/证件材料”页签，并正确标记当前页。
6. 带 `redirect` 切换页签时保留返回地址。
7. 现有客户资料表单转换、保存校验和材料上传测试继续通过。

### 7.2 staging 人工验收

1. 打开目标 A 线进件，`FINAL_VEHICLE_ALLOCATION` 显示车辆编号、车型、车牌或 VIN，不要求填写 UUID。
2. 点击“确认沿用已软锁车辆”后，人工任务完成且 Journey 进入订单和合同创建步骤；不产生新的最终方案版本或客户再次确认动作。
3. Portal 首页点击“我的资料”默认进入基本资料，能看见并保存省市区、详细地址和紧急联系人。
4. 点击“证件材料”页签可继续上传、预览和归档身份证、驾驶证等材料。
5. 从商品页携带返回地址进入资料页面，切换页签后返回地址仍有效。

## 8. 发布与恢复

- 本轮仅需 API/Web 新镜像，不执行数据库迁移。
- 部署后先确认容器镜像与目标 tag 一一对应，再进行上述人工验收。
- 若出现问题，可回滚 API/Web 镜像；数据库无新增结构或回填，无需数据库回滚。
