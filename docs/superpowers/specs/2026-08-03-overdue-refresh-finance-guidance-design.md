# 逾期刷新与未到期应收推进修复设计

## 背景

订单 `ORD20260802071556GFEY` 完成第 1 期里程复核后，系统正确生成了 1 元的独立超里程账单，状态为 `PENDING`，到期日为确认时间后 5 天。验收发现两个问题：

1. 订单工作台把未到期但尚未支付的应收账单显示成“已完成”，没有收款推进入口。
2. 逾期催收正式刷新在写审计日志时把 `overdue-refresh-YYYY-MM-DD` 写入 UUID 字段，导致接口返回 500；审计又发生在业务事务提交之后，存在业务已成功但接口报错的部分成功风险。

## 目标

- 未到期的未结清账单在订单工作台显示为非阻塞的“等待外部处理”，并提供“发起收款”入口。
- 到期和逾期账单继续显示为“待处理”，保持现有收款行为。
- 逾期正式刷新使用合法 UUID 作为批次审计实体标识。
- 逾期账单、催收案件、案件账单关联和本次刷新产生的审计日志在同一数据库事务内提交。
- 保持试算、到期日判断、T+5 规则和现有权限模型不变。

## 方案比较

### 方案一：仅替换审计实体 ID，并把未到期账单改成待处理

改动最少，但未到期账单会错误进入需立即处理的告警状态；审计若在事务提交后发生其他失败，仍会出现部分成功。

### 方案二：非阻塞等待状态 + 事务内审计（采用）

未到期账单使用 `WAITING_EXTERNAL`，仍提供 `finance.collect`，但不计入工作台告警数量。逾期刷新为每次正式运行生成 UUID，并通过支持事务客户端的 `AuditService.write` 在同一事务内写入刷新和催收案件审计。该方案同时满足操作可见性、非阻塞性、审计约束和原子性。

### 方案三：新增逾期刷新批次表

用独立实体持久化每次运行，可以支持更完整的批次历史，但需要数据库迁移和额外页面，超出本次缺陷修复范围。

## 详细设计

### 订单工作台

对 `PENDING`、`PARTIALLY_PAID` 且 `dueDate` 晚于当前时间的应收账单：

- 状态：`WAITING_EXTERNAL`
- 原因：沿用 `FINANCE_PAYMENT_NOT_DUE`
- 操作：`finance.collect`
- 定位对象：账单 UUID
- 阻塞：否

对到期或 `OVERDUE` 的未结清账单保持：

- 状态：`ACTION_REQUIRED`
- 操作：`finance.collect`

工作台已有“等待外部处理”状态展示和“发起收款”动作展示，因此不新增前端状态或权限，只调整后端工作台解析结果。

### 逾期正式刷新

正式刷新开始前生成一个新的 UUID，作为 `overdue_refresh` 审计记录的 `entityId`。日期、账单 ID 和数量继续保存在 `afterSnapshot` 中，不再把日期拼接字符串当作实体 ID。

`AuditService.write` 增加可选数据库客户端参数；默认仍使用全局 Prisma 客户端，现有调用不变。逾期正式刷新把事务客户端传入审计服务，并在业务事务返回前完成：

1. 更新符合条件的账单为 `OVERDUE`。
2. 创建或更新催收案件。
3. 创建或更新案件账单关联。
4. 写入刷新汇总审计。
5. 写入本次创建或更新的催收案件审计。

任一步骤失败都会回滚整个事务。试算继续提前返回，不写账单、案件或审计。

### 日期边界

逾期条件保持 `dueDate < asOfDate`，自然日差必须大于 0。到期当天不进入逾期，次日才进入 D1。本次账单到期日为 2026-08-08，因此截止 2026-08-09 才应进入逾期刷新。

## 错误处理与兼容性

- 不新增迁移，不改变账单或催收表结构。
- 不改变 T+5 到期日计算。
- 不改变 `billing:view`、`payment:create`、`collection:view` 等权限。
- 无 `payment:create` 权限时，工作台仍显示等待状态和账单定位，但动作由既有权限过滤逻辑移除。
- 审计写入失败时，正式刷新整体失败并回滚，不再产生部分成功。

## 测试设计

1. 工作台解析器：未来到期的未结清账单返回 `WAITING_EXTERNAL`、`FINANCE_PAYMENT_NOT_DUE` 和 `finance.collect`。
2. 工作台解析器：到期/逾期账单仍返回 `ACTION_REQUIRED`。
3. 逾期正式刷新：刷新汇总审计使用合法 UUID。
4. 逾期正式刷新：刷新和催收案件审计在事务有效期间写入；事务结束后的审计写入应使测试失败。
5. 逾期试算：仍不写审计或业务数据。
6. 回归：运行财务账单、订单工作台及相关 API 测试、类型检查、Lint、Prisma 校验和迁移状态检查。

## 验收标准

- 超里程账单生成后、到期前，订单工作台财务页签不再显示“已完成”，而显示“等待外部处理”，可进入收款流程。
- 到期前账单不进入逾期催收；到期次日试算能够命中。
- 正式刷新不再因审计 UUID 报 500。
- 正式刷新成功时业务数据和审计同时存在；失败时两者都不提交。
