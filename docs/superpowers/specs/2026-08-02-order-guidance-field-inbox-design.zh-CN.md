# 订单推进与 Field 交接任务体验修复设计

## 背景

2026-08-02 在 staging 对订单 `ORD20260802071556GFEY` 进行人工验收时，发现订单工作台、Portal 账单、Stage 2 通知状态和 Field 任务列表存在一组相互关联的体验问题。视频上传能力已通过 191.6 MB、1080P 原视频及 720P 替换视频验收，本设计不重做已经通过的上传链路，只修复仍未通过的项目。

本轮拆成两个可独立审查的 PR，并在两者合并后作为同一轮 staging 发布：

1. PR A：订单推进语义与 Portal 账单移动端布局。
2. PR B：交接通知状态、Field 打开回执、任务收件箱和资料提示。

## 已确认事实

### 合同“阻塞”属于误报

订单工作台对所有“合同已生成但尚未归档”的状态统一设置了 `blocking=true`。因此正常的待发起电子签和签署中状态也显示红色“阻塞”，但合同管理中的操作仍然可用。合同归档后该状态自然消失。

### 初始账单没有进入推进候选

工作台财务贡献者只识别已经存在的开放账单、支付失败、押金和催收事项，不识别“主合同已签署但初始账单尚未生成”。车辆交付准备又允许在合同签署后提前执行，因此车辆交接错误地抢占了下一步提示。

### 通知已经成功，页面停留在旧状态

本单的 `FIELD_HANDOVER_ASSIGNED` 短信任务和短信发送记录均为成功。Field 人员也已经通过认证后的任务详情接口多次打开任务。页面仍显示“等待系统重试”，原因是：

- 初次排队和重试等待共用了同一文案；
- Admin 获取初始排队状态后没有短轮询任务结果；
- 新版认证入口只记录 `TASK_VIEWED` 审计事件，没有同步交接工单已有的首次和最近访问时间字段。

### Field 列表排序与资料提示

Field 列表当前按预约时间升序排列，旧预约任务会排在新指派任务前；页面只有单一列表，状态标签也统一为蓝色。四个轮毂近拍项目允许照片和视频，前端因此误用了车辆环绕视频的质量提示。接口清单和页面遍历顺序已经保证“车辆环绕视频”位于“损伤/瑕疵静止近拍”之前。

## 目标与非目标

### 目标

- 正常合同待签不再误报阻塞，真正失败仍保留阻塞与恢复入口。
- 主合同签署后优先提示生成初始账单，并完成起租前收款后再突出车辆交接。
- Portal 账单列表在常见手机宽度下不被操作区挤压。
- Admin 能准确显示短信发送状态、失败重发能力以及 Field 是否打开任务。
- Field 任务按“活动中 / 已结束”分组，新任务优先，状态颜色有明确语义。
- 轮毂项目不再显示环绕视频提示，同时保持现有照片/视频兼容性。

### 非目标

- 不改变已经通过验收的视频上传、清晰度提取和替换流程。
- 不引入新的数据库表或迁移；使用现有工单访问时间字段和审计日志。
- 不把交付准备改成必须等待付款后才能操作；本轮只修复“主推进动作”的业务优先级。
- 不建设独立短信监控中心或新的消息队列系统。

## PR A：订单推进语义与账单移动端布局

### 1. 合同阻塞语义

订单工作台合同贡献者按以下规则输出：

- 尚未生成合同：待处理，但不阻塞。
- 合同已生成、待发起电子签、签署中：待处理，但不阻塞。
- 合同签署/归档完成：已完成。
- 合同任务明确失败且需要人工恢复：失败并阻塞。

前端仍根据 `blocking` 显示红色“阻塞”，不通过隐藏标签绕过后端语义错误。

### 2. “生成初始账单”推进候选

新增工作台动作 `finance.generate_initial_bills`。只有同时满足以下条件时产生：

- 订单不是终态；
- 主合同已签署或归档；
- 月费和押金金额有效；
- 至少一种必需的初始账单尚不存在。

零押金订单不要求生成押金账单；首期月费账单始终属于必需账单。动作跳转财务 Tab，并使用现有 `BILLING_GENERATE` 权限，不新增权限。

推进优先级为：

1. 合同生成/签署；
2. 生成初始账单；
3. 起租前账单收款或支付异常处理；
4. 推进车辆交接。

车辆交付准备仍可并行操作，但不能在初始账单缺失或未支付时成为工作台的首要建议。

### 3. Portal 账单响应式卡片

移除移动端脆弱的 `List.Item` 横向信息/操作布局，改为独立账单卡片：

- 信息区使用 `min-width: 0`，长账单号和订单号按整体可读片段换行；
- 状态、类型、金额和到期日使用结构化行展示；
- 桌面端操作按钮保持右侧排列；
- `<= 767px` 时操作区移动到卡片底部，按钮等宽或自适应排列；
- 已支付账单不显示无效的支付动作。

## PR B：通知回执、Field 收件箱与资料提示

### 1. 通知状态机与自动刷新

Admin 文案按任务真实状态区分：

- `PENDING` 且尚未尝试：`交接任务通知发送中`；
- `PENDING` 且存在失败尝试：`等待系统重试`，显示下次运行时间；
- `PROCESSING`：`交接任务通知发送中`；
- `COMPLETED`：`交接任务通知已发送`；
- `DEAD_LETTER`：显示最终失败原因，并提供现有的`重发交接任务通知`恢复动作。

指派成功后，Admin 对初次 `PENDING/PROCESSING` 状态执行有界短轮询，直到成功、最终失败或达到超时上限。对长时间延迟重试不做无限轮询。

### 2. Field 打开回执

认证后的 Field 任务详情成功返回时，在同一事务中：

- 首次打开时写入 `firstAccessedAt`；
- 每次打开更新 `lastAccessedAt`；
- 写入 `TASK_VIEWED` 审计事件。

Admin 摘要增加安全回执字段，只暴露是否打开及首次/最近打开时间，不暴露认证信息。对本轮发布前已经产生、访问字段为空但存在 `TASK_VIEWED` 审计记录的工单，读取时使用审计最早/最晚时间作为兼容回退，不执行批量数据回填。

页面状态：

- 未产生打开证据：`Field 尚未打开任务`；
- 已有打开证据：`Field 已接收任务`，显示首次打开时间。

这里的“接收”定义为目标 Field 人员完成认证并成功打开对应任务详情，不把短信送达本身等同于任务接收。

### 3. Field 任务收件箱

Field 列表分为：

- 活动中：可操作状态及等待客户、等待运营等尚未结束的状态；
- 已结束：`FIELD_COMPLETED`、`OPS_REVIEWED`、`CANCELLED`、`VOIDED`、`FAILED`。

已结束任务可以只读查看，但所有变更接口继续使用现有可编辑状态校验。排序规则：

- 活动中：优先显示需要 Field 操作的状态，同一优先级按指派/创建时间倒序；
- 已结束：按最近更新时间倒序。

颜色规则：

- 可操作/进行中：蓝色或青色；
- 等待外部动作：橙色或金色；
- 已完成/已复核：绿色；
- 失败：红色；
- 已取消/已作废：灰色。

API 返回稳定排序后的分组所需状态与时间，前端不再次按预约时间重排。

### 4. 资料提示与顺序回归

上传提示改为同时接收资料类型和允许媒体类型。只有 `WALKAROUND_VIDEO` 展示 720P/1080P 环绕视频质量提示。四个轮毂近拍继续兼容照片和视频，但使用与内饰近拍一致的通用入口提示。

“车辆环绕视频在损伤/瑕疵静止近拍之前”已经满足，本轮通过 API 清单和 Field 页面测试固定该顺序，不做生产数据重排。

## 错误处理与兼容性

- 账单候选读取失败沿用现有工作台降级策略，不把未知状态误标为已完成。
- 短轮询超时后保留最后已知状态，并允许用户手动刷新页面。
- Field 打开时间更新失败时任务详情请求应失败并记录日志，避免页面声称打开但审计缺失。
- 现有轮毂视频仍然有效，不因提示修正而变成不兼容资料。
- 已结束任务只获得读取能力，不恢复任何编辑或签署权限。

## 测试与验收

### API

- 正常待签合同 `blocking=false`，明确失败合同 `blocking=true`。
- 已签合同且缺少首期账单时，主动作是 `finance.generate_initial_bills`。
- 零押金订单只要求首期月费账单。
- 初始账单已生成未支付时，主动作切换为收款；收款后才突出车辆交接。
- 认证 Field 首次/再次打开正确写入访问时间和审计。
- 历史审计回退可生成打开回执。
- Field 活动/结束分组和排序稳定，结束任务不可编辑。
- 资料清单顺序保持环绕视频早于损伤近拍。

### Web

- 合同正常待签不显示红色阻塞。
- 新动作标签、图标、权限与财务 Tab 跳转正确。
- 320px、375px 和 390px 宽度下账单号、金额与操作按钮不互相挤压。
- 初始通知、重试、成功、最终失败文案及重发按钮正确。
- 初次排队状态触发有界轮询，终态后停止。
- Field 打开/未打开提示正确。
- 活动/已结束 Tab、排序和状态颜色正确。
- 轮毂项目不显示环绕视频提示，上传弹窗入口保持不变。

### Staging 回归

以新订单或可重复推进的测试订单验证完整链路：

1. 生成主合同后不出现误报阻塞；
2. 主合同归档后首先提示生成初始账单；
3. Portal 手机端账单列表正常；
4. 指派 Field 后通知状态自动更新为已发送；
5. Field 打开任务后 Admin 显示已接收；
6. Field 新任务位于活动列表顶部，结束后进入已结束 Tab；
7. 环绕视频、轮毂近拍和损伤近拍的顺序与提示正确。
